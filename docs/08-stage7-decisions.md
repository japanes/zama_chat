## Что сделано

- **Правила вопросов** (`decisions/policy.py`, таблица `decision_rules`). Правило — это
  шаблон ключа вопроса и что с ним делать:
  - шаблон: точный ключ (`wants_human`) или маска (`start:*`, `filter:booking.*`);
  - **режим** — кто отвечает:
    - `jev` — отвечает Jev (как раньше);
    - `llm` — отвечает только LLM (роль `decide`). Если LLM упала, отвечает Jev
      с любой уверенностью, в журнале причина `llm_error`;
    - `shadow` (теневой) — спрашиваются оба одновременно, используется ответ Jev, ответ
      LLM только пишется в журнал для сравнения. Если Jev не уверен или упал, берётся уже
      готовый ответ LLM, второй вызов не нужен. Стоит один вызов LLM на ход;
  - **порог** уверенности Jev (0–1). Действует только на Jev;
  - **что делать, если Jev ниже порога**:
    - `llm` — спросить LLM (как раньше);
    - `keep` — оставить ответ Jev как есть;
    - `ask_client` — ответа нет: поле не заполняется, проверка поля считается
      непройденной, бот переспрашивает клиента;
    - `operator` — то же, плюс ответ этого хода уходит оператору вариантами
      (как в режиме оператора). В песочнице ответ идёт как обычно.
  - Какое правило сработало: сначала точный ключ, потом самая длинная маска. Нет
    правила → Jev, порог 0.7, ниже порога — LLM.
  - Правила бывают общие (их меняет только суперадмин) и свои у тенанта. Своё правило
    с тем же шаблоном заменяет общее. Правила читаются в начале каждого хода, перезапуск
    не нужен.
  - Одно общее правило создаётся вместе с базой (миграция `4c97f46f4c0d`): `opt:*` —
    ниже порога «оставить ответ Jev». Это проверка, какие позиции каталога показать с

- **Журнал** `decisions`: новые причины `unsure` (Jev не уверен, правило «спросить
  клиента / оператор») и `llm_error`. Теневой ответ LLM — причина `shadow`, `used=false`.
- **Админка → «Решения»** (`/t/<тенант>/decisions`, только admin и owner):
  - карточки за период (1 / 7 / 30 / 90 дней): сколько вопросов, сколько ответил Jev,

    - гистограмма уверенности Jev (20 ступеней по 0.05), зелёным — где Jev совпал с LLM;
    - **симулятор порога**: двигаешь порог — видно, сколько вопросов уйдёт в LLM и

    - примеры расхождений Jev и LLM: переписанный текст, оба ответа, ссылка на диалог;
  - редактор правил: свои правила тенанта, общие (суперадмин) и подсказки по режимам.
- **Песочница**: новый выбор «Кто решает» — по правилам / Jev / LLM / оба (теневой).

- **`make eval`** (`backend/scripts/eval.py`, диалоги в `eval/dialogs/*.yaml`): прогоняет

  таблица расхождений Jev и LLM.

## Как пользоваться

```bash
make migrate                       # таблица decision_rules
make eval                          # все диалоги, модели с ролей
ONLY=interview make eval           # только файлы с «interview» в имени
SHADOW=1 make eval                 # Jev + LLM на каждом вопросе → совпадение в отчёте
DECIDER=llm make eval              # все вопросы решает только LLM
MODEL_REPLY=openai/gpt-6-luna EFFORT=low make eval   # другая модель / уровень размышления
```

`MODEL`, `MODEL_<РОЛЬ>` (REPLY, REWRITE, EXTRACT, DECIDE, VISION), `EFFORT`,
`EFFORT_<РОЛЬ>` (`off` — выключить) действуют только на этот прогон. Модель должна быть
заведена (`zama models add`). Перед первым прогоном: `make seed` (промпты) и модели на
ролях.

Подбор порога:
1. Админка → «Решения» → «Правила»: правило `*`, режим `shadow`. Неделю копится журнал.
2. Открыть вопрос, двигать порог в симуляторе: выше порога точность Jev должна быть
   близка к 100%, ниже — уходит в LLM.
3. «Применить порог» → сохранить правило с режимом `jev`.
