## Что сделано

- **Типы полей** (`scenarios/typed.py`). Значение сначала разбирает код, модель — только
  запасной путь:
  - `date` — «сьогодні», «завтра», «післязавтра», «у п'ятницю», «наступної п'ятниці»,
    `12.10`, `12.10.2026` (свои правила + dateparser). Настройки поля: `allow_past`,
    `max_days_ahead`. Часовой пояс — настройка тенанта `timezone`;
  - `time` — «15:00», «о 3 дня», «в 7 вечора»; остальное (диапазоны) — модели;
  - `phone` — phonenumbers, хранится в E.164 (`+380671234567`). Регион по умолчанию —
    настройка тенанта `phone_region`;
  - `email` (в нижнем регистре), `number` (`min`, `max`, `integer`);
  - `list` — список объектов (`item_fields`, `min_items`, `max_items`): групповая запись
    «Оля — манікюр, Іра — брови»;
  - `attachment` (`kinds`, `max_items`) и `receipt` — файл / чек из вложения;
  - код отклонил значение (дата в прошлом, короткий телефон) → поле частичное с
    пометкой `@<причина>`, бот переспрашивает своими словами, Jev не спрашивается;
  - телефон или email в сообщении одни, и в сценарии одно открытое поле такого типа →
    поле заполняется сразу, без модели извлечения.
- **Подтверждение** (`confirm:` в сценарии или `completion: explicit_yes`): когда всё
  собрано, бот показывает сводку и спрашивает «Усе вірно?». Вопрос Jev
  `confirm:<сценарий>` — yes / no / none. «Так» с исправлением в том же сообщении не
  считается «так». После «так» исправление снова требует подтверждения. Поле `receipt`
  спрашивается только после «так».
- **Ожидание CRM** (`completion: external_event`): после «так» сценарий получает статус
  `waiting`, уходит действие `on: waiting` (обычно `http_post` в CRM).
  - CRM отвечает на `POST /v1/events`:
    `{"result_id": "...", "event": "booked", "data": {...}, "event_id": "..."}`.
    Подпись: заголовки `X-Zama-Endpoint` (id адреса) + `X-Zama-Signature`
    (`sha256=HMAC(secret, тело)`, как у наших отправок), или обычный API-ключ;
  - что делает событие — правило в сценарии `events:`: `completed`, `cancelled` или
    `reopen` (снова спросить поля, например дату и время при `slot_taken`); `say` — слова
    бота клиенту, `{date}` — ответ клиента, `{data.booking_id}` — из события;
  - повтор с тем же `event_id` ничего не меняет (`duplicate: true`);
  - `waiting.hours` — сколько ждать CRM; потом сценарий закрывается как `abandoned`.
- **Несовместимые сценарии** (`incompatible_with`): пока открыт один, второй не
  запускается (в трассе — `blocked`). Пример: запись, перенос, отмена, групповая запись.
- **Одобрение действия** (`requires_approval: true` у действия): действие не выполняется
  сразу, а ждёт человека — задача оператора `approve_action` + уведомление. «Одобрить» —
  действие выполняется как было задумано, «Отклонить» — не выполняется.
- **Чеки** (`receipts/`):
  - клиент присылает фото квитанции → бот скачивает его (только публичные адреса, до
    `RECEIPT_MAX_MB`) → модель на роли `vision` читает сумму, валюту, дату, получателя,
    номер операции → **код** проверяет: сумма (с допуском), валюта, дата (не старше
    `max_age_days`, не из будущего), получатель (имя, конец карты или IBAN), статус
    платежа, повтор той же картинки или того же номера операции;
  - сумма — число в сценарии или из поля (`amount_field` = товар из каталога ×
    `quantity_field`);
  - «это не чек» / нечитаемо → бот просит прислать ещё раз;
  - дальше по настройке тенанта `receipt_review`: `always` (по умолчанию — каждый чек
    смотрит человек) или `issues_only` (человек смотрит только чеки с замечаниями;
    `receipt_review_above` — и все чеки выше суммы, например `{"UAH": 5000}`);
  - чек на проверке: сценарий ждёт (`waiting_for: receipt_review`), оператор получает
    задачу `review_receipt` с картинкой, прочитанным и замечаниями. «Принять» → заказ
    закрыт, клиенту «оплату підтверджено». «Отклонить» → бот просит правильную квитанцию;
  - каждый чек — строка в `receipts` (что прочитано, что ожидалось, замечания, кто решил).
- **API сообщений:** `POST /v1/messages` принимает `attachments`
  (`[{"type": "image", "url": "https://..."}]`); `text` теперь не обязателен, если есть
  вложение. В песочнице админки тоже можно отправить ссылку на картинку.
- **Сценарии** (`scenarios/`): `beauty_booking`, `reschedule_booking`, `cancel_booking`,
  `group_booking`, `prepaid_order` — перевод старых сценариев записи, переноса и отмены
  плюс заказ с предоплатой.
- **Админка:** в редакторе сценария — новые типы полей и их настройки, подтверждение,
  события CRM, ожидание, несовместимые сценарии, одобрение действия; в результате — чек
  (прочитанное и замечания); в очереди оператора — задачи «одобрить действие» и
  «проверить чек»; в настройках — `timezone`, `phone_region`, `receipt_review`.

## Как попробовать

```bash
make migrate
zama load-scenarios scenarios/ --channel <id канала>
# админка → Модели: модель с картинками назначить на роль vision
# админка → Песочница: «хочу записатися на манікюр у п'ятницю о 15»
# CRM: подтвердить запись
curl -X POST localhost:8000/v1/events -H "Authorization: Bearer <api key>" \
  -H 'Content-Type: application/json' \
  -d '{"result_id": "<id результата>", "event": "booked", "data": {"booking_id": "B-1"}}'
```
