# Как пользоваться приложением и проверять его

Все шаги ниже пройдены вживую 2026-10-05 на локальной машине, на настоящей модели.

Слова, которые встречаются дальше:

- **тенант** — один бизнес со своими настройками, сценариями и командой. Локально заведён один: `demo` («Demo salon»);
- **сценарий** — список вопросов, которые бот задаёт клиенту, плюс что делать с ответами (например, отправить в CRM);
- **результат** — то, что бот собрал по одному сценарию у одного клиента;
- **ход** — одно сообщение клиента и всё, что бот сделал в ответ.

## 1. Запуск

Одна команда из корня проекта — всё работает в Docker, в фоне:

```bash
make up        # то же, что docker compose up -d --build --wait
```

Она поднимает базу данных, поиск (Elasticsearch — по словам, Qdrant — по смыслу), сервер бота, фоновые задачи (отправка результатов, таймер тишины) и админку; перед стартом сама применяет миграции базы.

- админка — <http://localhost:3120>;
- сервер бота — <http://localhost:8090>; проверка, что он жив: <http://localhost:8090/health> показывает `{"status":"ok"}`.

Код подключён в контейнеры из папки проекта: после правки сервер бота, фоновые задачи и админка обновляются сами.

```bash
make ps                # что запущено
make logs              # логи всего; одной части: make logs s=api (worker, admin)
make zama c="models list"   # команда zama внутри контейнера
make down              # остановить
```

На сервере — файл `docker-compose.prod.yml`: готовые образы без подключённого кода, перезапуск после перезагрузки, база и поиск без открытых портов. В `.env` на сервере нужны `COMPOSE_FILE=docker-compose.prod.yml` и `POSTGRES_PASSWORD` (см. `.env.example`), дальше та же одна команда: `docker compose up -d --build`.

## 2. Вход в админку

1. Открыть <http://localhost:3120>.
2. Ввести почту админа, нажать «Отправить ссылку».
3. Под текстом «проверьте почту» появится блок «Ссылка (режим разработки)» — нажать на него.

Письма не отправляются: почтовый сервер не подключён, поэтому ссылка показывается прямо на странице.
Язык интерфейса (en / uk / ru) переключается вверху справа.

Нового админа создаёт команда `make zama c="create-user почта@example.com"`.

## 3. Что уже настроено в `demo`

- Языки бота: украинский и английский. На украинский и русский бот отвечает по-украински, на остальные языки — по-английски.
- Модель `openai/gpt-6-luna` стоит на всех задачах (ответ клиенту, переписывание вопроса, извлечение значений, решения).
- Включены 6 сценариев: `offer_interview`, `beauty_booking`, `cancel_booking`, `reschedule_booking`, `group_booking`, `prepaid_order`.
- Модель `openai/text-embedding-3-large` стоит на задаче `embed` — она превращает текст в числа, по которым бот ищет по смыслу.
- **Бот → Каталог**: 14 тестовых услуг салона (ногти, волосы, лицо, тело) с ценами.
- **Бот → База знаний**: текст «Правила салону» — дети, отмена записи, оплата, сертификаты, парковка, животные, гарантия.
- Собранные данные уходят на тестовый приёмник `http://localhost:8090/dev/sink/results`. Он заменяет CRM: просто сохраняет то, что ему прислали.

## 4. Проверка 1 — песочница (самая быстрая)

Меню: **Активность → Песочница**. Это чат с ботом от имени клиента. Ответ приходит за 10–15 секунд.

Полностью работает сценарий интервью (`offer_interview`). Сообщения по порядку:

| Написать | Что должен сделать бот |
|---|---|
| Хочу розібратися зі своєю пропозицією та позиціонуванням | Запустить сценарий и спросить про нишу |
| Я роблю манікюр у власному кабінеті на Подолі | Спросить, кто клиенты |
| А ви працюєте в неділю? | Ответить «так, щодня з 9 до 20» и **в том же сообщении** вернуться к вопросу про клиентов |
| Ой, я помилилась: я роблю не манікюр, а педикюр | Исправить нишу и снова спросить про клиентов |
| Жінки 25-40 років, які працюють в офісі | Спросить про основную услугу |
| Педикюр з покриттям гель-лаком | Спросить цену |
| 650 гривень | Спросить, чем отличается от других |
| Покриття тримається 4 тижні, даю гарантію | Поблагодарить; сценарий получает статус «Завершён» |

Что видно на странице:

- справа — сценарий, его статус и поля: какие заполнены, какое бот спрашивает сейчас;
- под ответом бота — **«Показать детали»**: переписанный вопрос клиента, решения бота (вопросы «да/нет», на которые он себе ответил), вызовы моделей, время и цена хода;
- **«Новый диалог»** или другое имя в поле «Тестовый клиент» — начать с нуля;
- «Модель ответа» и «Кто решает» — попробовать другую модель на один ход, настройки при этом не меняются.

**Важно:** песочница ничего не отправляет наружу — ни результатов, ни уведомлений, и таймеры в ней не работают. Это проверяется через API (проверка 2).

## 5. Проверка 2 — через API (так будет писать сайт или CRM)

В терминале, из корня проекта (нужна программа `jq`):

```bash
KEY=$(cat tmp/demo/api-key.txt)
say() {
  curl -s localhost:8090/v1/messages \
    -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
    -d "$(jq -n --arg t "$1" --arg c "${CLIENT:-test-1}" '{contact:{external_id:$c,name:"Тест"},text:$t}')" \
    | jq -r '.reply // "(бот молчит)"'
}

say "Хочу розібратися зі своєю пропозицією та позиціонуванням"
say "Я роблю манікюр у власному кабінеті на Подолі"
```

`say "текст"` — одно сообщение клиента, в ответ печатается ответ бота. Другой клиент — другое имя: `CLIENT=test-2 say "Привіт"`.

Ключ лежит в `tmp/demo/api-key.txt`. Новый ключ: админка → **Доступ → API-ключи**.

Когда интервью пройдено до конца:

- **Активность → Результаты** — строка со статусом «Завершён»; внутри поля и блок «Отправки во внешние системы» со статусом «Отправлено»;
- сам JSON, который получила бы CRM:
  ```bash
  curl -s localhost:8090/dev/sink/results | jq '.items[0].body'
  ```
  В нём `status: completed`, все поля словами клиента, `client_language` и `reply_language`.

## 6. Что ещё проверить

| Что | Как | Что должно быть |
|---|---|---|
| Служебные сообщения | «Привіт», «Ви бот?» | Короткий ответ, сценарий не запускается |
| Язык ответа | Написать по-русски; потом по-английски | На русский — ответ по-украински; на английский — по-английски |
| Вопрос о бизнесе | «What are your opening hours?» | Ответ по описанию бизнеса из **Бот → Настройки** |
| Цена из каталога | «Скільки коштує манікюр з гель-лаком?» | «650 грн» и что входит в услугу |
| База знаний | «А де у вас припаркуватися?», «Можно ли оплатить картой?» | Ответ по тексту «Правила салону» |
| Чего нет в базе | «А тату ви робите?» | Бот честно пишет, что не знает, и не выдумывает |
| Запись с выбором услуги | «хочу записаться», потом «Хочу на маникюр», потом «давайте другий» | На первое сообщение бот называет категории каталога (волосы, ногти, лицо, тело), на второе — показывает 2 маникюра с ценами, после выбора спрашивает про салон |
| Выбор по категории | «хочу записаться», потом «нігті» | Бот показывает 4 услуги для ногтей с ценами |
| Передача человеку (через API) | `say "Позовите менеджера"`, потом ещё одно сообщение | Бот пишет, что менеджер ответит, и дальше молчит. В **Активность → Оператор** появляется задача «Передан человеку»: можно написать клиенту и нажать «Вернуть боту» |
| Клиент замолчал (через API) | См. ниже | Через минуту в приёмник приходит JSON со статусом `incomplete` |

**Клиент замолчал.** По умолчанию бот ждёт 15 минут. Чтобы не ждать:

1. **Бот → Сценарии → offer_interview → Версии** — сделать активной версию 2 (в ней 1 минута). Или в разделе «Действия» у события «Клиент молчит» поменять «Через, минут» и сохранить новую версию.
2. Через API начать интервью новым клиентом, ответить на один вопрос и замолчать.
3. Через минуту: `curl -s localhost:8090/dev/sink/results | jq '.items[0].body'` — там `event: scenario.silence`, `status: incomplete`, заполненные поля и список `missing` (чего не хватает).
4. Если клиент потом допишет интервью, придёт ещё один JSON с тем же `result_id`, `seq: 2` и `status: completed`.
5. Вернуть версию 1 активной.

## 7. Где смотреть, что сделал бот

- **Активность → Диалоги** — все разговоры; у каждого хода «Показать детали». Диалоги песочницы видны с галочкой «Только песочница».
- **Активность → Результаты** — что собрано и куда отправлено; кнопка «Отправить ещё раз».
- **Бот → Каталог** и **Бот → База знаний** — что загружено и проиндексировано; внизу «Проверить поиск»: что бот найдёт по фразе и что из найденного пройдёт проверку Jev.
- **Бот → Решения** — как бот отвечал себе на вопросы «да/нет» и кто отвечал: Jev или запасная LLM.
- **AI-модели → Расходы** — сколько стоили модели по дням и задачам.
- **Доступ → Журнал изменений** — кто что поменял.

## 8. Что менять и сразу проверять

Любое изменение действует со следующего сообщения, перезапуск не нужен.

- **Бот → Сценарии** — вопросы, проверки ответов, когда сценарий запускается. Каждое сохранение — новая версия, старую можно вернуть.
- **Сценарии → Загрузить из файла** — сценарий, написанный текстовым файлом: проверяется и сразу становится рабочей версией. Как писать файл — `scenarios/README.md` (в админке: «Описание формата», там же готовый пример).
- **Бот → Промпты** — тексты-инструкции, по которым модель пишет ответы. Как бот задаёт вопросы сценария и показывает варианты — промпт `scenario_step`.
- **Бот → Настройки** — описание бизнеса (бот отвечает по нему), языки, правило «язык клиента → язык ответа».
- **AI-модели → Роли моделей** — какая модель делает какую работу.

Обычный круг: поменять → **Песочница** → «Новый диалог» → те же сообщения → сравнить ответ и детали хода.

## 9. Что сейчас не работает

- **Instagram, вход через Google, письма, уведомления в Telegram** — код есть, внешние аккаунты не подключены.
- **Чеки об оплате** (`prepaid_order`) вживую не проверялись.

**Про Jev** (быстрая модель для вопросов «да/нет»). В локальном `.env` стоит `JEV_ZERO_DATA_RETENTION=false`, с ним Jev работает: 14 вопросов за полсекунды. Со значением `true` бот просит Vercel не хранить тексты запросов, а Vercel принимает такую просьбу только на тарифах Pro и Enterprise — на бесплатном он отклоняет запрос (ошибка 403), и на все вопросы отвечает запасная LLM. Перед работой с настоящими клиентами решить: тариф Pro и `true` либо оставить `false`.

Замечено при проверке (нужна настройка промптов):

- на сообщение «Добрий день! Хочу розібратися зі своєю пропозицією, бо клієнти не розуміють, чим я краща» бот сначала отвечает «не можу точно сказати…» и только потом задаёт первый вопрос. На короткую фразу из таблицы выше отвечает нормально;
- один раз вместо вопроса про основную услугу спросил цену, а на следующем ходе спросил цену ещё раз;
- на вопрос «А з дитиною можна прийти?» бот ответил правильно, но заодно запустил сценарий групповой записи (`group_booking`) и спросил «хто прийде та на які послуги?». Нужно уточнить вопрос запуска этого сценария.

## 10. Автотесты

```bash
make test    # 947 тестов на подставных моделях: около 5 минут, без сети и денег
make eval    # 6 записанных разговоров на настоящих моделях, отчёт в tmp/eval/ (ещё не запускался)
```

5 тестов поиска идут на настоящем Elasticsearch и пропускаются, если он не запущен (`make up`). Самим тестам хватает базы: `make db`.
